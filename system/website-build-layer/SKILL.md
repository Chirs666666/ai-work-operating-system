# 1. Purpose
Coordinate website architecture, WordPress foundation, components, assembly, measurement, infrastructure, QA and deployment.

# 2. Trigger
Use for new-site builds, rebuilds, page additions, site expansion, migrations/launches and build-fix/relaunch work.

# 3. Do Not Trigger
Do not replace WB specialists or SEO Skills 01-25. Do not infer production approval, indexing or ranking.

# 4. Inputs
Project goal/scope, existing artifacts, specialist availability, environment, workflow mode and approvals.

# 5. Preconditions
Discover reusable artifacts and dependency state before routing work.

# 6. Workflow
DISCOVER → ROUTE → RUN/REUSE/VERIFY/SKIP → DEPENDENCIES → GATES → APPROVALS → HANDOFF → RECOVERY/CLOSEOUT.

# 7. Tool Routing
Use capability registry and workflow definitions. WB01-WB08 own build specialties; SEO Skills retain SEO specialties.

# 8. Decision Rules
REUSE requires evidence. Critical dependencies cannot be skipped. WB08 requires WB07 readiness plus production approval.

# 9. Quality Gates
PASS, WARN, FAIL, BLOCK, REUSE, WAITING_APPROVAL.

# 10. Outputs
Project state, artifact/dependency/routing/approval/gate/failure/recovery registers and cross-system handoffs.

# 11. Handoff
WB08 LAUNCH_VERIFIED routes to Skill 19; Skill 20 follows indexing/ranking workflow as appropriate.

# 12. Safety / Change Control
Production mutation remains explicit, scope-bound and approval-controlled.
