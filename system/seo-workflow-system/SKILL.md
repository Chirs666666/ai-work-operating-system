# 1. Purpose
Turn project goals into coordinated SEO and website-build workstreams.

# 2. Trigger
Use for multi-skill SEO, website building, publishing, migration, launch, indexing and growth workflows.

# 3. Do Not Trigger
Do not absorb specialist ownership, bypass approvals, infer indexing/ranking, or route merged Skill 14 directly.

# 4. Inputs
Goal, project/site scope, existing artifacts, requested environment/actions, approvals and specialist/subsystem availability.

# 5. Preconditions
Classify workstreams, discover artifacts, resolve aliases and dependencies before execution.

# 6. Workflow
GOAL → MASTER ROUTER → WORKSTREAMS → ARTIFACT DISCOVERY → ROUTING → DEPENDENCIES → GATES → APPROVALS → SPECIALISTS/SUBSYSTEM → RECOVERY → HANDOFF → CLOSEOUT.

# 7. Tool Routing
SEO capabilities route to 01–25; website engineering routes through Website Build Layer/WB01–WB08.

# 8. Decision Rules
REUSE requires evidence. 14 resolves to 12. WB08 requires WB07 readiness and production approval. UNKNOWN remains UNKNOWN/null.

# 9. Quality Gates
PASS, WARN, FAIL, BLOCK, REUSE, WAITING_APPROVAL.

# 10. Outputs
Shared project/workstream state, artifacts, routes, dependencies, approvals, gates, failures/recovery and handoffs.

# 11. Handoff
WB08 launch verification → 19 indexing → 20 ranking validation; continuous-growth specialists consume measured evidence.

# 12. Safety / Change Control
Publishing, URL/redirect/noindex/canonical/site/plugin/DNS/deployment/ads/paid-link actions remain explicitly approval controlled.
